# WRAITER 0.17.0 — Smoother manuscripts and everyday editing

Long chapters now keep their real layout while you scroll, so the page stays steady and paragraph numbers continue beside the right text. This release also reduces repeated work in large manuscripts, makes common editing gestures more familiar, and strengthens recovery when Windows or an office format refuses a save.

## Reading and navigation

- **Steady scrolling and margin numbers.** Removed the offscreen layout shortcut that changed paragraph heights while scrolling. Paragraph and page numbering follows the actual text, including after zooming and resizing the window.
- **Go to paragraph** through **Edit → Go to paragraph** or **Ctrl+G**. See the chapter's range and a preview before jumping. Existing custom Ctrl+G assignments are preserved.
- **Find stays with your passage.** Ctrl+F starts with selected prose and refocuses an existing query. Enter/Shift+Enter and F3/Shift+F3 move through matches while keeping the query usable; Escape returns to the passage. Matches beyond the ordinary highlight limit are revealed and highlighted when selected, and the results list stays on their page.
- **Shared document zoom** through the menu, keyboard, percentage control and Ctrl+mouse wheel, while retaining your reading position.

## Everyday editing

- **Drop or paste images** into the manuscript, including clipboard screenshots and batches of supported image files. Resize a selected image with proportional corner handles, or edit its dimensions and description in a dialog. Changes are undoable and image dimensions travel through WRAITER, ODT and DOCX saves.
- **Drop documents into project tabs** and drop text or Markdown files into the references panel. Mixed drops explain which files were accepted.
- **Reorder chapters and tabs by dragging.** Rename a chapter with a double-click or F2. Middle-click closes a project tab, and tab context actions apply to the tab you clicked.
- **Familiar link actions.** Ctrl+click opens a link; Ctrl+K and the native context menu support editing and removing it.
- **More reliable keyboard focus.** Font lists remain visible in short windows, support normal Tab/Shift+Tab navigation, and return focus after choosing or dismissing. Dialogs focus their first input and preserve a distant manuscript selection when closed.

## Performance and save recovery

- Editor configuration, Find highlights, comment locations and editing-history status reuse unchanged data. Statistics does not analyse the whole manuscript again when only the page estimate changes.
- Identical recovery and native-state snapshots avoid another disk replacement only after verifying the existing bytes. Changed data still uses flushed atomic writes, and named-source conflict checks remain active.
- ODT encoding parses bounded batches of paragraph XML while retaining the same document content and format checks.
- Brief Windows replacement locks receive bounded retries. A lasting lock preserves the original file and complete recovery draft.
- Invalid ODT text, titles or font metadata produce an actionable save error instead of silently altering XML. An office encoding failure still preserves the full recovery draft, private notes and undo history, including across closing and restarting.

A matched six-run benchmark on a synthetic 120,000-word manuscript reduced median return to a large tab from **1.74 seconds to 1.20 seconds**, about **31%**. Startup and typing did not show consistent overall improvements. The [development measurements](../OVERNIGHT-WORK.md) distinguish complete desktop timings from focused helper benchmarks.
