# WRAITER 0.21.0-rc.4 — account password document access

Signing in now creates or unlocks encrypted document storage with the account password. There is no routine separate document passphrase or recovery-key setup. Browser session caching keeps document access through reloads and new tabs; another device opens the same library after signing in. Desktop uses operating-system-backed encrypted storage for its cached document key and validates the cloud session before restoring access.

Existing beta vaults migrate once using their original document passphrase or recovery key. Migration rewraps the same random encryption key and leaves documents, notes, references, conversations and editing history unchanged. The server continues to store only encrypted document content, wrapped keys and salted authentication hashes.

Account password changes update authentication and the wrapped document key atomically. A forgotten-password reset preserves the encrypted library; recovering its key needs a trusted browser that still has access, the previous password, or an earlier saved recovery key. An inaccessible existing vault is never silently replaced.

The change includes account/session binding, cache expiry and sign-out handling, fresh-device access, browser and desktop interoperability, legacy migration, password change/reset preservation and isolated packaged desktop checks. Production deployment preserves existing user data and private configuration and verifies the updated backup.
