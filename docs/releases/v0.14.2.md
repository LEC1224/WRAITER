# WRAITER 0.14.2 — Windows file opening

This local Windows build fixes opening WRAITER manuscripts from Explorer. It has not been published as a GitHub release.

## Changes

- The installer adds **Associate .wraiter files with WRAITER**, checked on a fresh installation and remembered on upgrades.
- Registered manuscripts have the WRAITER icon and open command, and WRAITER appears in Windows' Open with and default-app choices.
- Double-clicking a manuscript opens it in WRAITER, including when the application is already running. Already-open files reuse their tabs.
- Current typing is saved before switching; requests received during startup or a dialog wait for the editor to be available.
- Opting out or uninstalling removes WRAITER's registrations and preserves other applications' entries and default choices.

## Local downloads

- `WRAITER-0.14.2-Setup.exe` — guided Windows installer.
- `WRAITER-0.14.2-Windows.exe` — portable application.
- `WRAITER-0.14.2-SHA256SUMS.txt` — checksums for both executables.

These are Windows x64 builds. Existing Windows default-app choices may still need to be changed through **Open with → Choose another app → WRAITER → Always**.

## Validation

213 unit tests, development and packaged file-opening tests, isolated installer registration tests, project-tab regressions, and packaged onboarding passed. The final wizard was checked visually, including preserving an unchecked choice through Back/Next.

The broader tutorial test has an existing checkpoint-summary assertion failure that also reproduces in 0.14.1. See [the validation report](../../TEST-REPORT.md) for the comparison and exact checksums.
