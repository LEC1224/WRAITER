Your writing and your data

WRAITER Cloud beta · Updated 11 November 2026

WRAITER Cloud is operated by LEC1224. For privacy, support or account questions, contact carl.1224@outlook.com.

Document encryption and sign-in

Current WRAITER clients encrypt document titles and complete document contents on your device before upload. Contents include chapters, images, notes, references, comments, editing history, saved checkpoints and assistant conversations. The server stores encrypted envelopes and a wrapped document key, rather than the unwrapped document key.

Your account password also opens your documents. A key derived from that password using PBKDF2 protects a random document key; AES-GCM encrypts the documents. New accounts do not need a separate document passphrase or a saved recovery key. The account password is sent over HTTPS to authenticate you and is stored only as a salted hash. Because the same password also protects the document key, this service could capture a password during authentication and decrypt stored documents. This design protects stored copies; it does not provide secrecy from an actively malicious service.

To reopen your documents without another prompt, the browser remembers a CryptoKey in its local IndexedDB database. It stores neither your password nor raw key bytes. This cache is bound to your account, authenticated session and exact encrypted vault version, and is used only after the server confirms your sign-in. Signing out, an expired or revoked session, or an account switch clears the cached key. Clearing browser site data also removes it. The desktop app can remember its document key using the operating system's protected credential storage. Sign out on shared devices.

Changing your password while signed in protects the same document key with the new password and preserves your documents. Resetting a forgotten password also preserves the encrypted documents. A trusted browser with a matching cached key can reconnect them after the reset. On another device, the previous account password is needed to recover access. If no usable trusted copy or previous password remains, those documents cannot be decrypted; resetting the password does not replace or erase them.

Accounts from an earlier release may need their separate document passphrase or existing recovery key once. WRAITER then connects the same document key to the account password. Existing recovery keys remain usable where present; new accounts do not require one. Keep any existing recovery key private.

Information the service can read

Your email address, salted account password hash, account settings, document identifiers, storage sizes, revision numbers and access times remain readable to the service. Passwords are never stored as plaintext. Confirmation, password reset and account session tokens are stored as hashes. Account settings do not include provider API keys or document keys.

Cloudflare handles HTTPS. A transactional email provider sends confirmation and password reset links for the site you opened. Server and proxy logs may record connection addresses, request metadata and errors. Document contents and titles are encrypted in document requests.

The web app is delivered by this service. A changed or compromised app could capture text or secrets while you use it. Encryption of stored documents does not remove the need to trust the app delivered to your device.

Earlier documents and backups

Earlier WRAITER Cloud releases stored documents without client-side encryption. The updated client encrypts those documents after signing in and opening the existing document key. A conflicting change pauses migration so an older copy is not silently overwritten.

Migration replaces the live document record. Earlier plaintext may remain in historical database pages, backups or storage snapshots after migration; those copies require separate maintenance. The update does not claim that historical plaintext has already been erased.

A scheduled backup copies the cloud database, including documents, accounts and settings, to the publisher’s other PC at the operator’s backup drive. New encrypted records remain encrypted in that copy. Deleted data can remain in the existing backup until that copy is replaced. Server and backup administrators can read account metadata and any remaining legacy plaintext, and can access encrypted records for maintenance.

Browser recovery

While you write, WRAITER saves encrypted recovery drafts in this browser’s local storage database. Recovery drafts can remain after you sign out. They are decrypted only after you sign in and the corresponding account’s document key is available. Recovery records from an earlier release are encrypted when you next open that account’s documents.

Use the recovery download and discard controls in your library to manage unsynchronized drafts. Clearing browser site data removes browser recovery copies. Download important recovery drafts before discarding or clearing them.

Your AI connection

AI is optional. The web app connects directly from your browser to a supported cloud API provider using your own API key. Prompts, provider responses and API keys do not pass through the WRAITER document server. The web app does not run local generative models or use the publisher’s Codex subscription.

Your API key is held in the current browser session’s memory and sent only to your selected provider over HTTPS. It is not saved in cloud settings, documents or backups. Reloading or signing out clears it. Your provider charges your own account for API use.

AI requests send relevant writing, selected passages, instructions, enabled references and assistant conversation context to your provider. Its terms and data handling apply. Private notes and comments are excluded from prompts by WRAITER’s writing tools. Turn AI off in Settings to stop AI requests. Local spelling, grammar and thesaurus tools are separate from cloud generative AI.

Downloads, limits and deletion

Each account has 1 GB of cloud storage. Encrypted document data, editing history, embedded images, references, conversations, saved checkpoints, encryption envelopes and account settings count toward that limit. Encryption adds storage overhead. A single document and its history may use up to 64 MB before encryption. The web release keeps up to 20 saved checkpoints per document.

Individual downloads and the Download library ZIP contain decrypted documents. The ZIP contains WRAITER files, original editing journals and a document manifest. Extract it to open the WRAITER files in the desktop app. It does not include account passwords, API keys or document keys. Keep these downloaded files private.

Delete individual cloud documents from the library. Deletion removes the active cloud document, its saved history and checkpoints. Browser recovery copies are separate and can be discarded in the library. Account deletion removes the account and its documents from the active database and signs you out. Deleted data can remain in existing backups or historical storage copies until those copies are replaced or separately maintained.

Beta service

This is an early release. Keep a downloaded copy of important documents. WRAITER does not include advertising, sell document contents or automatically share your library with other users.
